# Sutellite web application workflow

## User experience

The application opens on a globe-first landing page. The globe uses an orthographic projection and shows the eight built-in study areas as selectable markers. Country-level study areas are also highlighted on the globe; California is represented by its own regional marker rather than colouring the entire United States. Users can select a marker or use the region cards below the globe.

Selecting a region opens its workspace:

1. A spatial cell map with a **2D / 2.5D** view toggle.
2. A sensor/platform/processing-stream/year filter panel.
3. Summary metrics for observation records, detection cells, active observation days, land-cover labels, filtered observations, FRP and statistical anomalies.
4. A collapsible **Analysis & monitoring** panel with four sections:
   - **Statistics:** monthly activity and sensor/platform/stream breakdowns.
   - **Anomalies:** the exploratory robust historical anomaly flags generated by `src.cell_aggregation`.
   - **AI detections:** model prediction CSVs when `SUTELLITE_AI_RESULTS_DIR` is configured.
   - **Hotspot calendar:** daily source-observation-record counts for the selected month, coloured by relative activity.
5. A separate collapsible cell-data and downloads section.

The landing page also contains the FIRMS CSV upload workflow. It supports the eight named regions and a user-defined region with a WGS84 GeoJSON boundary. Successful uploads create a canonical Parquet output and the region's spatial products, then open the corresponding workspace.

## Data flow

```text
Globe / region selection  OR  FIRMS CSV upload
                 |
                 v
      src.upload_pipeline
                 |
                 v
      Canonical Parquet
                 |
                 v
       src.cell_aggregation
        |       |        |
        |       |        +--> daily_activity.parquet
        |       +----------> monthly_activity.parquet + monthly_anomalies.csv
        +------------------> cell_aggregates.parquet + cell_breakdown.parquet
                 |
                 v
       Streamlit region workspace
        |        |          |          |
        2D/2.5D  Statistics  Anomalies  Hotspot calendar
                 |
                 v
          GeoJSON / Parquet / CSV downloads
```

## Required configuration

Set `SUTELLITE_CANONICAL_DIR` to the shared `canonical_v1.1` folder. Set `SUTELLITE_WORLDCOVER_DIR` to a local folder of ESA WorldCover 2021 tiles when available. Set `SUTELLITE_AI_RESULTS_DIR` to a folder containing per-region prediction CSVs produced by `python -m ai.run_model` if AI predictions should appear in the application.

The large canonical Parquet data, regional boundary files and WorldCover tiles are not included in the Git repository. The current prototype uses the eight region names and globe markers, but precise study-region polygons are not bundled. Built-in CSV uploads therefore need to have been filtered to the selected region. Custom-region uploads require a GeoJSON Polygon or MultiPolygon in EPSG:4326 and are clipped to that boundary.

## Daily hotspot calendar

`src.cell_aggregation.build_cell_products` writes `daily_activity.parquet` and `daily_activity.csv`, grouped by region, acquisition date, sensor, platform and processing stream. The calendar sums those daily observation records using the current region workspace filters.

Calendar colour intensity is based on daily record counts. A date with no row is not interpreted as zero fire activity, and it does not establish that a satellite observed the location. Source records are detections, not unique fire events.

## AI vs statistical anomaly outputs

The Anomalies section uses the robust historical method implemented in `src.cell_aggregation.detect_monthly_anomalies`. It is not an AI model.

The AI detections section reads a matching regional CSV from `SUTELLITE_AI_RESULTS_DIR`. Existing model inference code and model card describe a separate experimental model. If no trained-model prediction CSV is configured, the application displays a clear unavailable state instead of presenting statistical flags as AI predictions.

## Run locally

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

The app opens at `http://localhost:8501`.

## Interpretation constraints

- A row is a satellite detection record, not a unique fire event.
- The grid is angular (latitude/longitude degrees), not equal-area.
- MODIS and VIIRS nominal resolutions and confidence systems differ.
- Absence of a detection row is not proof of zero activity or satellite non-observation.
- The daily calendar counts source observation records; it does not infer coverage.
- WorldCover is shown only where local tiles and a usable sample are available. Missing labels display as **No data**.
- Anomaly flags and AI model outputs are exploratory and are not operational fire alerts or forecasts.
